# 평창꽃순이김치 AI Agent v2.0 상세 설계

- 작성일: 2026-09-30
- 상태: 추천 방향 승인 완료, 상세 설계 검토 대기
- 대상: 기존 `v2/` React·TypeScript·FastAPI 서비스
- 설계 방향: LOT 중심 현장 업무와 근거형 AI 대화 통합

## 1. 목표와 사용자

사용자는 현재 잘 작동하는 플랫폼을 김치공장 업무에 특화하고, 모바일을 반드시 고려한 평창꽃순이김치 AI Agent v2.0으로 개선하도록 요청했다. 대화에서 제안한 통합형 방향은 승인되었다.

현장 작업자와 품질 담당자를 우선 사용자로 가정한다. 공장장은 같은 현장 홈에서 확인 대상 기록을 살펴볼 수 있다. 역할별 로그인이나 별도의 관리자 대시보드는 이번 범위에 추가하지 않는다.

대표 작업은 “주의 기록 선택 → 해당 LOT와 연결 공정 확인 → AI에 질문 → 답변 근거 확인”이다. 모바일에서는 첫 화면에서 확인 대상 선택 후 두 번의 주요 조작 이내에 선택 LOT를 대상으로 질문할 수 있어야 한다. 질문 전송은 사용자가 실행한다.

명칭은 헤더와 브라우저 제목에 `평창꽃순이김치 AI Agent v2.0`으로 통일한다. 기존 녹색 계열 브랜드와 한국어 업무 용어를 유지한다.

## 2. 현행 기반과 문제

- 기존 V2에는 문서·원본 테이블 조회, LOT 선택, 추천 질문, AI·데모 대화, 실시간 음성, 근거 내려받기가 있다.
- `/api/workspace`, `/api/lots/{lot_id}`, `/api/documents`, `/api/tables/{table}`을 재사용할 수 있다.
- LOT 상세 응답에는 상위 세척 CCP, 금속검출, PDA 이동, 출하가 포함된다. 프런트엔드 `Detail` 타입에는 `metal`, `movements`가 빠져 있어 실제 계약과 맞춰야 한다.
- 현재 3열 화면은 901~939px 구간에서 열 최소 너비 합계가 화면보다 커질 수 있다. 작은 글씨와 34~38px 버튼도 현장 모바일 사용에 불리하다.
- 문서 또는 테이블 조회 실패가 전체 화면 오류로 이어지고, 새로고침 중 Assistant가 언마운트되어 대화가 사라질 수 있다.
- LOT 변경 시 현재 대화가 초기화된다. 화면 이동·LOT 변경·초기화의 의미를 분리해야 한다.
- 실제 API는 AI 요청마다 `previous_response_id=None`을 사용한다. 화면에 이전 대화를 보존하는 기능과 서버가 여러 질문을 연속 추론하는 기능을 구분한다.

설계 전 기준 검증: 프런트엔드 production build 통과, `v2/tests` 12개 통과. 브라우저·실기기 검증 결과는 구현 후 별도로 기록한다.

## 3. 범위

### 이번 버전에 포함

1. 현장 홈과 확인 대상 목록.
2. LOT 검색·필터·상세·공정 계보.
3. LOT 문맥을 사용하는 AI 질문과 기존 음성 기능.
4. 한국어 근거 표시와 원본 열람.
5. 자료 검색·테이블 조회·추천 질문·질문 이력의 접근성 유지.
6. PC·태블릿·모바일 탐색과 같은 탭 내 대화 상태 유지.
7. 화면별 로딩·빈 결과·오류·재시도 및 반응형 검증.

### 후속 범위

실제 MES/PDA·센서 연결, PostgreSQL 전환, 배합 최적화, 발효 예측, QR 스캔, 오프라인 저장·동기화, 사용자 계정·기기 간 업무 인계, 출하 승인 쓰기 기능은 이번 구현에 포함하지 않는다. 기존 확장용 업무·인증 서버 모듈은 재사용 가능한 상태로 유지하되 연결되지 않은 기능을 화면에서 제공한다고 표시하지 않는다.

## 4. 화면과 탐색

주요 탐색은 `현장`, `LOT`, `AI`, `자료` 네 항목이다. 기본 진입은 현장이다. 화면과 선택 LOT는 URL hash에 표현해 새로고침과 브라우저 뒤로 가기에 대응한다. 접근 코드·질문·답변은 URL에 넣지 않는다. 존재하지 않는 화면 값은 현장으로 복귀하고, 잘못된 LOT는 오류와 선택 해제 동작을 제공한다.

### 현장

- 상단에 샘플 표시, 기록 기준일, 마지막 조회시각을 함께 둔다. `오늘 현황`이라는 제목은 사용하지 않는다.
- 세척 CCP 주의 기록, 금속검출 보류 기록, 출하 품질 승인 대기 기록, 재고 부족 기록을 분류별로 표시한다.
- 숫자는 실제 조회 결과의 행 수다. 한 LOT가 여러 분류에 들어갈 수 있으므로 합계를 고유 LOT 수나 종합 위험 점수로 표시하지 않는다.
- 세척은 `result`가 있는 기록 중 `적합` 이외, 금속검출은 `result`가 있는 기록 중 `적합` 이외, 출하는 `quality_approval`이 있는 기록 중 `승인` 이외를 대상으로 한다. 판정이 없으면 별도 `미확인` 표시를 사용한다.
- 재고 부족은 수량·안전재고가 모두 유효한 숫자일 때만 `quantity < safety_stock`으로 표시한다. 샘플 안전재고 기준임을 표시한다.
- 분류 순서는 고정하며 AI가 산출한 위험 순위라고 설명하지 않는다. 출하 대기 원인은 관련 원본을 확인하기 전 추론하지 않는다.
- LOT가 있는 항목은 상세로 이동한다. LOT가 없는 재고 항목은 품목 기록을 열고 전체 기록 대상 질문을 제안하며 임의 LOT를 연결하지 않는다.

### LOT

- LOT 번호·제품명 검색과 공정·기록 상태 필터를 함께 제공한다. 복합 필터는 AND 조건이다. 결과 수와 필터 초기화를 표시한다.
- PC는 목록과 상세를 나란히, 모바일은 목록에서 상세로 전환하고 `목록으로` 버튼을 제공한다. 뒤로 가면 검색·필터를 복원한다.
- 상세는 LOT 번호, 제품, 공정, 수량·단위, 상태, 기록시각으로 시작한다.
- 공정 계보는 실제 `parent_lot_id` 연결을 표시한다. 원료 입고·세척·절임·혼합·충진·포장이라는 공정 안내에서 기록이 없는 단계는 `연결 기록 미확인`으로 표시하며 가상 LOT를 만들지 않는다.
- 세척 CCP, 금속검출, PDA 이동, 출하를 독립 영역으로 제공한다. 조회 성공 후 데이터가 없을 때 `기록 없음 / 미확인`으로 표시하며 `정상`으로 해석하지 않는다.
- `이 LOT에 질문`은 LOT 문맥과 질문 초안을 AI 화면으로 전달한다. 자동 전송하지 않는다.

### AI

- 선택 LOT와 AI/데모 모드를 질문 입력 영역 가까이에 표시한다.
- 상황 질문은 `상위 세척 CCP와 금속검출 기록 확인`, `출하 승인 상태와 연결 근거 확인`, `PDA 이동 기록 확인` 등 기존 조회가 지원하는 범위로 구성한다.
- 기본 답변은 현재 API의 실제 텍스트를 유지한다. 화면이 임의 요약이나 새로운 판정을 만들지 않는다.
- 근거는 식별자, 측정값·단위, 기록시각, 원본 판정, 출처 순으로 정리한다. 원본 JSON과 내려받기는 계속 제공한다.
- 알 수 없는 레코드 종류는 공통 키·값 목록으로 표시한다. null은 `미확인`, 숫자 0은 `0`으로 구분한다.
- 선택 LOT와 질문에 적힌 LOT가 다르면 기존 서버 검증 오류를 표시하고 초안을 보존한다.
- 추천 질문과 질의이력은 AI 화면의 접을 수 있는 영역에 둔다. 이력 질문을 선택하면 현재 대상 LOT를 확인할 수 있는 초안으로 채운다.
- 실시간 음성의 시작·음소거·종료와 문자 입력을 유지한다. 화면을 AI에서 벗어나거나 LOT·모드를 바꾸면 마이크와 재생을 종료한다. 다시 AI 화면으로 와도 자동 재시작하지 않는다.
- 음성 오류는 AI 영역에 표시하고 문자 질문을 계속 사용할 수 있게 한다.

### 자료

- `지식문서`와 `데이터허브` 탭을 유지한다.
- 문서 제목·본문 검색, 담당자·개정·승인 상태·문서 ID·본문을 제공한다. 응답에 없는 메타데이터는 `미확인`으로 표시한다.
- 허용된 11개 테이블만 선택할 수 있다. 테이블 조회는 페이지당 20건, 이전·다음 이동, 현재 조회 범위를 표시한다. 마지막 페이지 여부는 응답 행 수와 테이블 건수를 사용하며 새로고침 후 건수 변화도 반영한다.
- 문서나 기록 상세는 키보드 접근 가능한 dialog로 열고 닫으면 호출 버튼으로 포커스를 돌린다.

## 5. 반응형·접근성

| 화면 너비 | 동작 |
| --- | --- |
| 1200px 이상 | 왼쪽 탐색, 업무 본문, 오른쪽 AI. AI 탐색 선택 시 대화를 넓게 표시 |
| 768~1199px | 간결한 탐색과 업무 본문. AI는 요청 시 전체 높이 패널로 표시 |
| 767px 이하 | 한 열 본문, 하단 4개 탐색, AI 전용 화면, LOT 상세에서 목록 복귀 |

- 320px까지 페이지 전체 가로 넘침이 없어야 한다. 긴 표만 자체 컨테이너에서 가로 스크롤한다.
- 주요 조작 버튼과 모바일 탐색 터치 영역은 최소 48×48px, 모바일 입력 글씨는 최소 16px로 한다.
- 기본 본문은 14~16px, 주요 업무 값은 16px 이상으로 제공한다. 상태는 색과 텍스트를 함께 사용한다.
- 배경은 밝은 중립색, 녹색은 탐색과 주요 실행, 주의·보류는 의미가 있을 때만 별도 색상을 쓴다. 외부 폰트 로딩 실패 시 시스템 한글 폰트로 정상 렌더링한다.
- AI 입력 영역은 `100dvh`, safe-area inset과 유연한 스크롤 영역을 사용한다. 키보드가 열렸을 때 전송 버튼이 접근 가능해야 한다. 고정 최소 높이로 모바일 viewport를 밀어내지 않는다.
- AI 화면에서는 하단 탐색을 입력 영역과 겹치지 않게 배치한다. 패널을 닫으면 원래 업무 화면과 스크롤 위치로 복귀한다.
- 패널·dialog는 Escape 닫기, 포커스 복귀를 지원한다. 모달 패널이 열리면 배경으로 키보드 초점이 이동하지 않는다.
- 메뉴·버튼·입력은 의미 있는 accessible name을 제공한다. 숨겨진 PC/모바일 UI는 탭 순서에서도 제거한다.
- 200% 확대, 긴 한국어 문서명, 긴 LOT 식별자, reduced-motion을 확인한다.

## 6. 데이터 계약과 컴포넌트 경계

기존 API 경로와 DB 스키마를 유지한다. 초기 홈 데이터는 `/api/workspace`와 `/api/tables/metal_detection`에서 읽으며, 금속검출은 limit 100의 페이지를 마지막까지 조회한 뒤 건수를 확정한다. 일부 페이지 실패는 0건으로 표시하지 않고 해당 분류의 오류로 표시한다. `/api/workspace`의 CCP 응답은 주의 기록 전용이므로 정상 포함 전체 세척 목록으로 오해하지 않는다.

LOT 상세는 `/api/lots/{encodeURIComponent(lotId)}`를 사용한다. `Detail` 타입에 실제 응답의 `metal`, `movements`를 추가한다. 문서·근거 타입에는 서버가 제공하는 `revision`, `owner`, `status` 등의 메타데이터를 반영한다.

구성 책임은 다음과 같이 나눈다. 파일명은 구현 시 동일 책임을 유지하는 범위에서 조정할 수 있다.

| 구성 | 책임 |
| --- | --- |
| `App` / WorkspaceShell | 탐색, 선택 LOT, 반응형 배치, 연결 설정 |
| OperationsHome | 기록 분류·건수·확인 대상 탐색 |
| LotWorkspace / LotDetail | 검색·필터·공정 계보·관련 기록 |
| EvidenceRecord | 레코드 종류별 한국어 필드 표시, 원본 펼침 |
| ResourceLibrary | 문서 검색·본문·테이블 페이지 조회 |
| Assistant | 질문·답변·음성 UI와 통합 전송 경로 |
| 대화 상태 hook | LOT·모드별 대화·초안, 요청 취소·경합 방지 |

별도 UI 프레임워크나 상태 관리 라이브러리는 추가하지 않고 기존 React와 lucide-react를 사용한다. 기존 `journey.css`는 현재 진입점에서 사용하지 않으므로 새 화면에 통째로 연결하지 않는다. 적용되는 스타일을 중심으로 공통 토큰과 새 화면 스타일을 정리한다.

## 7. 상태·요청·오류 처리

- 선택 LOT, 검색·필터, 탭은 화면 이동으로 초기화하지 않는다.
- 대화와 입력 초안은 브라우저 탭의 메모리에 LOT 및 AI/데모 모드별로 보관한다. 전체 기록 대화는 별도 문맥이다. 다른 LOT로 돌아오면 해당 대화를 복원한다.
- 브라우저 새로고침은 URL의 화면·LOT만 복원한다. 대화의 디스크 영구 저장이나 기기 간 동기화는 제공하지 않는다. 이 동작을 UI의 대화 안내에 명시한다.
- LOT·모드 변경 시 진행 중 요청을 취소한다. 요청 세대 ID로 늦게 도착한 답변이 다른 문맥에 들어가지 않게 한다. 단순 탐색 이동은 진행 중 문자 질문을 취소하지 않는다.
- 질문 전송은 단일 경로를 사용하고 중복 전송을 막는다. 오류·취소 시 초안을 보존하고 같은 질문을 재시도할 수 있게 한다.
- 초기 필수 workspace 실패는 전체 오류와 재시도, 문서·금속검출·LOT 상세 실패는 각 영역 오류로 처리한다.
- 새로고침은 실제 API를 재조회하지만 Assistant를 제거하지 않는다. 실패하면 마지막 성공 데이터와 조회시각을 유지하고 갱신 실패를 표시한다.
- LOT A에서 B로 빠르게 바꾸면 A의 늦은 상세 응답을 무시한다. 필터·테이블·문서 검색도 같은 원칙을 적용한다.
- 대화 초기화는 현재 LOT·모드의 답변과 초안을 지우며 진행 중 응답·음성을 취소한다. 일반 화면 이동과 명확히 구분한다.

## 8. 근거의 의미와 연결 상태

모든 제조 기록은 2026-09-04 샘플이며 문서·규칙은 미승인이다. 기록 기준일과 실제 조회시각을 구분한다. 값과 판정은 원본 기록의 표시이며 새로운 안전 한계나 출하 허가를 뜻하지 않는다.

`데모 조회`는 정해진 기록 검색, `AI`는 서버 AI 호출이라는 기존 구분을 유지한다. API 키 미설정 시 데모 사용은 가능하고 음성 시작은 연결 설정으로 안내한다. 연결 확인은 서버 설정·권한 확인이며 유료 모델 응답 검증과 구분한다.

API 키는 서버에서만 사용하고, 기존 접근 코드 처리와 유료 엔드포인트 보호를 유지한다. 현재 `V2_REQUIRE_LOGIN=1` 배포에는 로그인 UI가 없으므로 이번 버전이 조직 로그인 지원을 완료한다고 문서화하지 않는다.

## 9. 수용 기준과 검증

### 업무 시나리오

1. 현장 홈에서 샘플 금속검출 보류 기록을 선택하고 `PACK-260904-01` 상세를 연다.
2. 상위 `WASH-260904-01`과 실제 CCP·금속검출 기록이 연결되어 표시된다.
3. `이 LOT에 질문`으로 초안을 만들고 사용자가 전송한다. 답변과 근거의 대상 LOT가 일치한다.
4. 자료 화면으로 이동한 후 돌아와도 동일 LOT와 대화가 유지된다.
5. 다른 LOT에서 질문한 다음 원래 LOT로 돌아오면 대화가 섞이지 않고 복원된다.
6. 기록이 없는 영역은 정상 대신 미확인으로 표시된다. 누락 공정은 가상의 실제 공정으로 연결되지 않는다.
7. 새로고침·문서 조회 오류·상세 조회 오류가 기존 대화를 지우지 않는다.

### 자동 검증

- `npm run build --prefix v2/web` 통과.
- 기존 `v2/tests` 회귀 검증 통과.
- LOT 상위 근거와 Detail 계약, 누락·0 값 구분, 금속검출 페이지 수집 실패, 느린 응답 경합, LOT별 대화 유지에 대한 의미 있는 테스트를 추가한다.
- 공유 Python 코드 변경이 발생할 경우 기존 `tests`도 실행한다.

### 브라우저 검증

- 360·390·768·1024·1440px에서 홈·LOT·AI·자료를 확인하고 320px에서 넘침을 추가 점검한다.
- 모바일 목록→상세→질문→근거, 뒤로 가기, LOT 전환, 대화 초기화, 새로고침을 실제 UI로 확인한다.
- 키보드 탐색, 모달 포커스, 200% 확대, 긴 이름, 오류·빈 결과를 확인한다.
- 실제 휴대전화 키보드·마이크·Safari 검증은 사용 가능한 실기기에서 수행한 경우에만 완료로 보고한다. 데스크톱 viewport 검증으로 대체했다고 주장하지 않는다.
- 실제 유료 AI·음성 호출, 외부 배포, Docker 빌드는 수행 여부를 별도로 보고한다.

## 10. 전달물과 검토 경계

구현 완료 시 개선된 `v2/` 소스, production build, 실행 방법, 변경 설명, 테스트 결과, 확인한 PC·모바일 화면을 전달한다. 로컬 확인과 외부 서비스 배포는 구분한다.

이 문서는 대화에서 승인된 방향을 구체화한 상세 설계이며 제품 구현 완료를 뜻하지 않는다. 상세 설계 승인 후 brainstorming 절차의 다음 단계인 writing-plans로 구현 계획을 작성하고, 계획 검토와 실행 방식 선택 후 제품 코드를 변경한다.
