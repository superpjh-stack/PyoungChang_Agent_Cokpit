# 평창꽃순이김치 AI Agent v2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` after the user selects Native execution. Check off steps as they are completed.

**Goal:** 현장 작업자와 품질 담당자가 PC·태블릿·모바일에서 샘플 확인 대상 LOT를 따라가며 기존 근거형 AI에 질문할 수 있도록 V2를 개선한다.

**Architecture:** 기존 Vite React 앱과 FastAPI의 읽기 전용 조회 API를 유지한다. React 앱 셸이 URL과 화면 내 업무 문맥을 소유하고, 현장 홈·LOT 상세·자료·Assistant를 역할별 컴포넌트로 분리한다. LOT 선택별 대화와 초안은 앱이 살아 있는 탭 메모리에 보존한다.

**Tech Stack:** React 19, TypeScript, Vite 7, FastAPI, 기존 SQLite 데모 데이터, lucide-react, 기존 CSS.

**Spec:** [2026-09-30-kkotsuni-v2-design.md](../specs/2026-09-30-kkotsuni-v2-design.md)

## Global Constraints

- V1 Streamlit은 계속 실행 가능해야 하며 변경이 없으면 V1 테스트를 추가하지 않는다.
- 기존 DB 스키마와 허용된 읽기 전용 API를 유지한다. Client-side SQL과 임의 API 호출은 추가하지 않는다.
- 제조 기록은 2026-09-04 샘플이고 문서·규칙은 미승인임을 보인다. 실제 없는 값은 미확인으로 나타낸다.
- UI 상태·색은 새 승인 판단이나 AI 위험 점수처럼 표시하지 않는다.
- 입력 글씨는 모바일 16px 이상, 주요 터치 영역은 48×48px 이상, 최소 320px에서 전체 페이지 가로 넘침은 없다.
- 공급자 키는 서버에서만 사용한다. 사용자가 질문을 전송하며 CCP·출하를 자동 승인하지 않는다.
- 새 의존성을 도입하지 않는다. 기존 `v2/web/package-lock.json`을 유지한다.

## Review Focus

이 항목들은 가장 가능성 높은 화면 입력·조건이므로 소유 Task에서 구현 점검 목록에 연결한다.

- 이름이나 LOT 번호가 긴 한국어 입력이 화면을 넓히지 않음 — Task 6 모바일 뷰 점검.
- 2026-09-04 기록의 0과 null이 구별됨 — Task 1 근거 뷰 표시 점검.
- 페이지 또는 분류 조회 실패를 정상·0건으로 잘못 표시하지 않음 — Task 2 상태 메시지 점검.
- 사용자가 LOT A→B로 빨리 전환했을 때 늦게 온 A 상세·응답이 B에 표시되지 않음 — Task 3 및 Task 4 동작 점검.
- viewport 높이보다 긴 답변·근거와 모바일 키보드가 전송 버튼을 가리지 않음 — Task 6 모바일 뷰 점검.

**`EvidenceRecord`**는 `record: Row`, `kind: 'ccp' | 'metal' | 'movement' | 'shipment' | 'inventory' | 'generic'`, `onOpenSource?: (record: Row) => void`를 받는다.

**`LotDetail`**는 `detail: Detail`, `onAsk: (question: string, lotId: string) => void`, `onBack: () => void`를 받는다.

**`OperationsHome`**는 `data: Workspace`, `metalRecords: Row[]`, `metalError: string`, `onOpenLot: (lotId: string) => void`, `onAsk: (question: string, lotId?: string) => void`를 받는다.

**`ResourceLibrary`**는 `documents: Document[]`, `tables: TableInfo[]`, `onDocumentsReload: (query: string) => Promise<void>`, `onRows: (table: string, page: number) => Promise<Row[]>`를 받는다. 기존 Assistant와 연결 설정은 props로 전달한다.
